# 深圳大学粤海校区周边三维协同取件仿真
先打开 gust_recovery.mp4 观看订单 41 的突发风况和地面接回。用 Blender 4.3 打开 SZU_Yuehai.blend，按空格播放、滚轮缩放、中键旋转。在大纲中选 TRUCK 或 UAV 并按小键盘句点聚焦。时间轴第 67 帧标记了地面接回事件。模型车辆按米制尺寸，蓝、橙两条线分别表示卡车道路行程和无人机实际飞行轨迹。默认动画为强风启发式组，一帧约对应 10 秒仿真时间。
## 实施计划及交付
1. 获取粤海校区及周边 OSM 路网、建筑闭合轮廓、水体和绿地，转换为局部东、北、上坐标。
2. 建立路网、建筑、车辆、取件点与风场模型，运行相同订单和车辆参数的对照。
3. 保存每次分配的输入、实际耗电和 XYZ 轨迹，重建 Blender 动画，导出应急事件局部回放。
4. 验证各组订单仅服务一次、包裹载重、电量守恒、时间单调及卡车回仓。
## 数据和场景
中心为 WGS84 (113.933°E, 22.532°N)，取数范围 [113.913,22.514,113.953,22.550]。源自 © OpenStreetMap contributors，按 ODbL 1.0 提供。数据来源 https://api.openstreetmap.org/api/0.6/map ，地图版权 https://www.openstreetmap.org/copyright 。data/map.json 是冻结的派生数据，随本项目按 ODbL 提供。图层对齐均用同一套 WGS84 转换；局部平面近似，地面高程设零。
数据包含 2031 段道路折线、11665 个道路形状或连接节点、2106 个建筑轮廓和 406 个水域/绿地要素。209 个建筑采用 OSM 高度，857 个按层数乘 3.2 m，1040 个按类型估算。建筑只提取完整的闭合 way 外轮廓，未还原多边形关系内洞、楼顶设备、地形或树冠。建筑体量为 LoD1。OSM 标签值未作现场核验。
车辆沿有向道路图按时间最短路行驶，区分道路等级、单行线和部分车辆通行标签。55 个订单、仓库点、重量和截止时间均为合成，固定在路网最大强连通分量的道路节点，点间至少 155 m。客户场地被设为可着陆并可由卡车访问。道路速度按等级设定，未引入实测交通、门禁、转弯限制、临停或真实空域许可。卡车合计载重上限 500 kg，纯取件时可用包裹总重校验。
## 模型与算法
config.json 控制种子、订单数、电池容量、安全储备、载荷及速度等。默认电池容量 756 Wh，20% 安全阈值为 151.2 Wh，可规划使用 604.8 Wh。电量降到阈值时，卡车在当前节点用 120 秒更换为满电电池。最大快递载重 2 kg，巡航空速 16 m/s，空载和满载耗电率分别为 25 Wh/km 和 50 Wh/km。航线用建筑轮廓外扩 5 m 检查，飞行高度至少为相交最高建筑加 12 m，超出 120 m 模型上限则拒绝。
卡车每到一个节点重新观测天气。风从东、东北、北、西北、西、西南、南、东南八个方向中选取，常规风况为 0–8 m/s，完整环境覆盖 0–14 m/s。规划对 5 种预测风扰动逐一检查，并同时检查完整任务能耗和最坏地速下的安全距离。执行按实际仿真风场求顺逆风地速。当前将风场在单航段内近似为常值。飞控姿态、任意位置失效处置、禁飞区和流体动力学不在本版计算中。
truck 为全卡车；normal/gust 使用最近邻确定的客户序列，在每个停靠点按观测风速重新分类并比较车机并行或卡车串行的预计用时。0–8 m/s 使用常规风况，8–14 m/s 使用强风筛选，达到 14 m/s 或没有安全可行航程时仅派卡车。gust_milp 在同一强风场下滚动求解固定序列子问题，最多展望接下来 14 个节点。目标包含卡车里程、能耗、完成时间、客户延误和可选的换电成本。HiGHS 的时限 1.5 秒，目标间隙 3%，不证明整条路线的全局最优性。
## 重现实验
使用 Linux、Python 3.10+、numpy、scipy >=1.9（包含 scipy.optimize.milp）、GDAL Python 绑定 osgeo。读取冻结地图即可运行。当前交付在 Blender 4.3.2 中生成。指令在本目录执行。
```bash
python3 simulate.py
python3 verify.py
blender -b -P build_scene.py -- "$PWD"
python3 replay.py
```
视频生成另需 Pillow、FFmpeg、Noto Sans CJK 字体。若改用其他系统，应在 replay.py 指定可用的中文字体文件。replay.py 针对默认种子中首次出现的地面接回事件，若参数修改后无此事件，直接查看结果 JSON 或 Blender 全程动画。map_build.py 是可选的原始 OSM XML 转换器，常规复现实验请使用冻结的 map.json 和 config.json。
## 如何读结果
results/summary.csv 为四组汇总。各组 JSON 的 audit 给出客户、会合点、节点观测风速与方向、天气分类、安全距离、可动用电量、完整航程最大预测能耗和派单原因。weather_observations 保存每个卡车节点的观测，battery_swaps 保存换电时刻和换电前后电量。battery 为实际电量记录，orders 为客户完成时间和延误，truck/drone 为 [秒,东米,北米,高度米]。
应急后包裹由无人机在客户处完成取件，最终由卡车接走，计入无人机取件与地面接回各一次。未起飞的候选任务拒绝计数与在途接回计数应分开。一次实验不能估计真实事故率。对比同一策略的 normal/gust 可观察天气效应，对比 gust/gust_milp 可观察分配策略效应。
